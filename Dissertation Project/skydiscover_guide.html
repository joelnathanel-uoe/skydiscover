What is SkyDiscover?

SkyDiscover automates program/prompt search using LLMs. You provide a starting solution (optional) and a scoring function. The framework repeatedly asks an LLM to produce improved variants, evaluates them, and accumulates the best into a database. Over many iterations it approaches — and often matches or beats — human-designed state-of-the-art solutions.

It introduced two new algorithms — AdaEvolve and EvoX — and benchmarked them across 200+ tasks in math, systems, GPU kernels, and competitive programming. On 14 evaluated systems/math tasks it matches or exceeds AlphaEvolve (DeepMind) and human SOTA.

How it works — The Core Loop

Every iteration is the same five-step cycle:

→
step 2
Build prompt
context_builder/
→
step 3
Generate

→
step 4
Evaluate
evaluation/
→
step 5
Store
search/
↑ ─────────────────────────── repeat ─────────────────────────────── ↓
  1. Sample — the search algorithm picks a parent solution (and optional context solutions) from the database.
  2. Build prompt — the context builder assembles the parent, context, problem description, and any feedback into system + user messages for the LLM.
  3. Generate — the LLM produces a new candidate (code diff, full rewrite, or plain text).
  4. Evaluate — your scoring function runs the candidate and returns a numeric score (and optional artifacts).
  5. Store — the scored candidate is added back to the database, closing the loop.

The DiscoveryController in search/default_discovery_controller.py orchestrates this loop. Algorithms that need custom cross-iteration logic (e.g. island rotation, co-evolution) subclass it and override run_discovery().

Repo Components

Search / Database
skydiscover/search/
The brain of the loop. Maintains the solution database and decides which solutions to use as parents each iteration. Each algorithm is a subpackage here.
  • base_database.py — abstract base
  • adaevolve/ — multi-island adaptive
  • evox/ — co-evolving strategy
  • topk/, beam_search/, best_of_n/
  • default_discovery_controller.py — loop runner
  • registry.py — maps flag names → classes
Context Builder
skydiscover/context_builder/
Assembles the exact prompt sent to the LLM each iteration — the parent solution, example programs, problem description, feedback, and instructions.
  • default/ — standard code/text prompts
  • adaevolve/ — intensity-aware prompts
  • evox/ — includes strategy context
  • gepa_native/ — Pareto-aware prompts
  • human_feedback.py — injects live feedback
LLM Layer
skydiscover/llm/
Wraps LiteLLM to support any provider. Handles retries, timeouts, streaming, token limits, and multi-model weighted pools.
  • llm_pool.py — weighted model sampling
  • openai.py — LiteLLM-backed client
  • agentic_generator.py — tool-use agent mode
Evaluation
skydiscover/evaluation/
Runs your scoring function in a subprocess and parses the result. Supports three formats auto-detected at startup.
  • evaluator.py — Python evaluate(path) function
  • container_evaluator.py — Docker-based
  • harbor_evaluator.py — Harbor benchmark format
  • llm_judge.py — LLM-as-a-judge scoring
  • wrapper.py — cascade evaluation + retries
Runner / Config / API
skydiscover/runner.py · api.py · config.py · cli.py
Wires everything together and exposes the two entry points.
  • runner.py — initialises all components, starts the loop
  • api.py — run_discovery() / discover_solution()
  • cli.py — skydiscover-run command
  • config.py — YAML loading + CLI overrides
Extras + Utils
skydiscover/extras/ · skydiscover/utils/
External algorithm backends and shared helpers.
  • extras/ — OpenEvolve, GEPA, ShinkaEvolve wrappers + live monitor dashboard
  • utils/code_utils.py — diff parsing, EVOLVE-BLOCK extraction
  • utils/metrics.py — score tracking, diversity
  • utils/async_utils.py — concurrency helpers

Algorithms

⭐ AdaEvolve
--search adaevolve
Multi-island search with UCB island selection, EMA-based adaptive intensity, periodic migration, paradigm breakthroughs, and a quality-diversity archive. Best overall choice — especially strong at ≤50 iterations.
🧠 EvoX
--search evox
Co-evolves both the solution and the search strategy itself using a second LLM loop. Strategy evolution unlocks step-change improvements in longer runs (≥50 iterations).
🎲 Best-of-N
--search best_of_n
Simple baseline — generates N variants from the same parent then picks the best. Fast and cheap, good for quick sanity checks.
🔍 Beam Search
--search beam_search
Maintains a beam of top solutions and expands all of them each iteration. Broader exploration than Top-K.
📊 Top-K
--search topk
Always mutates the best-known solution, using the next K as context. Minimal setup, good first experiment.
🗺️ OpenEvolve Native
--search openevolve_native
Native port of OpenEvolve's MAP-Elites quality-diversity grid with island-based ring migration. No external install needed.

Demo — Circle Packing

Pack 26 non-overlapping circles in a unit square and maximise the sum of their radii. The seed program uses a naive ring layout (score ~0.4). The AlphaEvolve paper reached 2.635 (score = 1.0). This is the official quick-start benchmark — it has a live monitor enabled out of the box.

1
Install uv
SkyDiscover uses uv for dependency management. Skip if you already have it.
curl -LsSf https://astral.sh/uv/install.sh | sh
source $HOME/.local/bin/env    # or restart your terminal
2
Install dependencies
Run from the repo root.
cd /root/skydiscover
uv sync
uv sync --extra math
3
Set your OpenAI key
export OPENAI_API_KEY="sk-..."
4
Run the experiment
Use gpt-4o-mini and 10 iterations to keep it fast and cheap. A dashboard URL will print at startup.
uv run skydiscover-run \
  benchmarks/math/circle_packing/initial_program.py \
  benchmarks/math/circle_packing/evaluator.py \
  --config benchmarks/math/circle_packing/config.yaml \
  --search adaevolve \
  --model gpt-4o-mini \
  --iterations 10
The live monitor dashboard is enabled in the config. Open the printed URL (e.g. http://localhost:8765) to see a scatter plot of all programs, code diffs, scores, and AI summaries updating in real time.
What the LLM is doing: receiving the current best packing code → proposing a diff → the evaluator checks for overlaps and boundary violations → scores sum-of-radii / 2.635 → best programs persist into the next round.
5
Try a different algorithm on the same problem
uv run skydiscover-run \
  benchmarks/math/circle_packing/initial_program.py \
  benchmarks/math/circle_packing/evaluator.py \
  --config benchmarks/math/circle_packing/config.yaml \
  --search evox \
  --model gpt-4o-mini \
  --iterations 10
6
Replay a finished run
uv run skydiscover-viewer outputs/checkpoint_10

What to expect

IterationsTypical scoreWhat the LLM discovers
0 (seed)~0.4Naive concentric rings, lots of wasted space
10~0.6–0.75Hexagonal grids, tighter spacing
50~0.85–0.95Mixed-radius layers, better boundary use
100~0.95–1.0+Approaches / matches AlphaEvolve (2.635)
Score = sum_of_radii / 2.635. A score of 1.0 means you matched the AlphaEvolve paper result.

Extending SkyDiscover

What you wantWhat to do
Run your own problemWrite evaluator.py with an evaluate(program_path) → dict function returning combined_score. Optionally add initial_program.py with # EVOLVE-BLOCK-START/END markers.
New search algorithmSubclass ProgramDatabase in skydiscover/search/, implement add() and sample(), register in route.py. See topk/ (56 lines) as the minimal example.
Custom LLM promptingSubclass ContextBuilder in skydiscover/context_builder/. See context_builder/README.md.
Containerised evaluatorCreate a directory with a Dockerfile + evaluate.sh that writes JSON to stdout. Point skydiscover-run at the directory.
External benchmark suiteUse Harbor format: directory with instruction.md + environment/Dockerfile + tests/test.sh. AlgoTune, EvoEval, BigCodeBench, USACO, and more work out of the box.
Evolve text / promptsPass a .txt file as the initial program and set language: text + diff_based_generation: false in config.
